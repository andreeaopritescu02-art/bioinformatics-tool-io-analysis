# BWA Analysis

## Tool Overview

BWA (Burrows-Wheeler Aligner) is a sequence alignment tool for mapping DNA sequencing reads against a reference genome.

Repository:
https://github.com/lh3/bwa

The repository was analysed using GitHub Copilot, followed by manual verification against the BWA source code, documentation and the EDAM ontology.

The analysis distinguishes between formats used by the core BWA commands and outputs generated only by the auxiliary `bwakit` pipeline.

## Input Files

| Input | Format | Data type | Status |
|---|---|---|---|
| Sequencing reads | FASTQ | Sequence reads with quality scores | Confirmed |
| Reference sequence | FASTA | Reference genome sequences | Confirmed |
| Sequence reads in BAM | BAM | Sequence reads | Confirmed |

### Evidence

Manual verification:

- `bwa.1` documents FASTQ input for `bwa mem`, `bwa aln` and other alignment commands.
- `README.md` provides examples using FASTQ reads and FASTA references.
- `bwa.1` documents FASTA as the required format for the `bwa index` command.
- `bwa.1` documents the `-b` option for BAM sequence-read input.
- `bwtaln.c` confirms BAM input handling for `bwa aln`.

### Input Format Details

#### FASTQ

FASTQ is the primary sequencing-read input format. BWA supports standard FASTQ input and compressed FASTQ through the sequence input library.

Compression is treated as a property of FASTQ rather than as a separate biological format.

#### FASTA

FASTA is used as the reference sequence format. The reference is processed by `bwa index` to create the BWA FM-index.

#### BAM

BAM can be used as an alternative sequence-read input for `bwa aln` with the `-b` option.

This represents BAM input containing sequencing reads and should not be confused with BAM alignment output generated by `bwakit`.

The results were then manually checked against the BWA source code and documentation.

An important distinction identified during verification was that the BWA repository contains both the core BWA aligner and the auxiliary `bwakit` pipeline.

Therefore:

- SAM is a core BWA output;
- SAI is a BWA-backtrack intermediate format;
- `.bwt`, `.pac`, `.sa`, `.ann` and `.amb` are BWA reference index components;
- BAM, HLA reports and log files are generated by `bwakit`, not directly by the core BWA alignment commands.

The primary output of the core BWA alignment commands is therefore SAM.

Intermediate and Reference Files
SAI

bwa aln produces .sai files containing intermediate alignment information used by bwa samse or bwa sampe.

Example:

bwa aln ref.fa reads.fq > reads.sai

Manual verification:

bwa.1, lines 13 and 383-385;
README.md, lines 103-112;
bwase.c, lines 529-570.

SAI is a proprietary BWA-specific binary format and does not have a specific EDAM format term.

BWA FM-index

The bwa index command creates five reference index components:

Extension	Component
.bwt	Burrows-Wheeler Transform
.pac	Packed reference sequence
.sa	Suffix array
.ann	Sequence annotations
.amb	Ambiguous base positions

Manual verification:

bwtindex.c, lines 267-322;
bwakit/run-bwamem, lines 51-52;
bwa.1, lines 46-74.

These files are proprietary BWA index structures and are not treated as standard bioinformatics formats.

BWAKIT Outputs

The BWA repository also contains the bwakit auxiliary pipeline.

These outputs are reported separately because they are not generated directly by the core BWA alignment commands.

EDAM Mapping Limitations

The coding agent could not programmatically parse the complete EDAM.owl file, so the verification is documented as manual rather than programmatic.
Unsupported / Excluded Formats
Generic Binary Format Mapping

The BWA-specific SAI and FM-index files are not mapped to a generic binary EDAM term because doing so would imply a standard format equivalence that is not supported by the repository.

They are therefore reported as proprietary formats without a specific EDAM identifier.

Compression

Gzip compression is not treated as a separate biological format. A compressed FASTQ file remains FASTQ data with a compression layer.

SAM Tags

SAM optional tags such as NM, MD, AS, XA and XS are fields within the SAM format and are not separate formats.

Output Mechanisms

Standard output (stdout) and redirection to .sam files are output mechanisms rather than formats.

AI Evaluation

GitHub Copilot was useful for identifying the major input and output formats and locating relevant source-code evidence.

Manual verification was necessary to distinguish between:

standard bioinformatics formats;
BWA-specific intermediate formats;
BWA reference index components;
outputs of the auxiliary bwakit pipeline.

One important distinction was that BAM alignment output is not a direct output of the core BWA commands. Core BWA produces SAM, while the bwakit pipeline converts and processes the alignment to produce BAM.

The EDAM mappings suggested by the coding agent were also reviewed manually. Standard mappings for FASTQ, FASTA, SAM and BAM were retained, while proprietary BWA-specific formats were left unmapped rather than assigning unsupported generic terms.

This demonstrates that coding agents are useful for repository exploration, but their results require manual verification against source code and ontology information.

Final Conclusion

BWA accepts FASTQ sequencing reads, FASTA reference sequences and, for bwa aln, BAM sequence-read input.

The primary output of the core BWA alignment commands is SAM.

The BWA-backtrack workflow also produces SAI intermediate files, while bwa index creates the proprietary .bwt, .pac, .sa, .ann and .amb reference index components.

The repository additionally contains the bwakit pipeline, which can generate BAM alignment files, HLA genotype reports and diagnostic log files. These outputs are clearly separated from core BWA outputs.

The final EDAM mappings are:

FASTQ → format_1930
FASTA → format_1929
SAM → format_2572
BAM → format_2573

The analysis distinguishes between standard formats, proprietary BWA files, intermediate files and auxiliary pipeline outputs, based on evidence from the BWA repository and manual verification.
